# Panlume 2.0 阶段 6：高 DPI、滚动与零终端流程

## 本阶段完成内容

- 新增唯一 Windows DPI 初始化入口，在创建 Tk 根窗口前设置 Per Monitor V2。
- 没有同时使用 DPI manifest 和其他 DPI API；PyInstaller 配置未增加重复入口。
- Tk scaling 每个根窗口只初始化一次，使用实际 DPI 换算。
- 滚动绑定记录已处理控件，避免重复绑定；Text/Treeview 保留自身滚动行为，滚轮只作用于指针所在区域。
- 页面空闲回调统一登记，销毁时取消未执行回调并解除滚动绑定，避免关闭后的无效回调。
- 页面滚动不重建整页控件，长报告使用可选择复制的独立滚动文本框。
- 新增图形化 CSV 历史回放：分钟、前复权日线、交易日历和可选回放时刻均可选择，无需终端。
- CSV 回放明确确认后按现有清洗/冲突规则去重写入当前数据目录，不访问网络或模型。
- 新任务继续沿用活动任务去重、按钮恢复、错误日志和关闭保护。

## 关键设计说明

1. `configure_windows_dpi()` 只调用 `user32.SetProcessDpiAwarenessContext(-4)`，并只在主入口、根窗口创建前执行。
2. 初次实机检查纠正了 DLL 归属：该 API 属于 `user32`，不是 `shcore`。
3. `initialize_tk_scaling(root)` 用根窗口标记避免重复初始化；多显示器实际效果仍需人工验收。
4. `ScrollablePage` 只绑定普通控件，不使用 `bind_all`；动态新增控件可补绑定，已绑定对象不会重复处理。
5. 销毁页面时取消 `after_idle` 并解除绑定，后台任务完成回调仍通过主线程 UI 队列。
6. CSV 回放复用 `CsvReplayAdapter` 和既有 ingest 清洗/冲突逻辑，没有第二套数据入口。

## 尚未执行的 Windows 实机验收

以下项目未在本轮擅自修改显示设置，也未构建新 EXE，需要人工逐项验收：

### 100%、125%、150%、175%、200% 缩放

每个比例重新启动应用后检查：

1. 字体、按钮、输入框、图标和表格没有明显模糊或裁切。
2. 980×640 小窗口的 12 个导航入口、主要按钮和状态文本可见。
3. 报告中心长文本可滚动、选择和复制，弹窗按钮可达。
4. 模型管理列表和下载进度不超出窗口。
5. 鼠标滚轮一次只滚动一个预期区域，Text/Treeview 不被父页面抢占。

### 多显示器与分辨率

1. 在 1080p 和 2K 显示器分别启动，记录系统缩放比例。
2. 在不同 DPI 显示器之间来回移动窗口，检查清晰度、字体、图标和点击坐标。
3. 移动后继续滚动、输入、打开报告和模型弹窗，确认没有错位或重复滚动。
4. 切换主题并打开/关闭页面，确认没有销毁后的无效回调。

### 后台任务与关闭

1. 报告生成、CSV 回放、模型下载期间重复点击，确认不会启动同名第二任务。
2. 活动任务期间尝试关闭，确认保护提示仍出现。
3. 取消/失败后按钮恢复，无自动重试，详细错误写入运行日志。

Linux 或其他平台结果不能代替上述 Windows 验收；本轮没有把这些项目写成已通过。
