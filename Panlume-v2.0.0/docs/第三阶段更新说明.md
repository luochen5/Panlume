# 盘灯第三阶段更新与验收说明

> 历史说明：本文记录当时的第三阶段安装过程，保留结构版本 4、99 项测试和旧止损口径作为历史证据。当前使用请改看 `第四阶段A更新说明.md`、`第三阶段收尾记录.md` 和项目根目录 README；现行结构版本为 5，固定止损采用触及或跌破即提醒，历史分钟缺口与有效当前分钟止损已经解耦。

## 1. 这次更新做什么

第三阶段在既有模拟行情、CSV 回放和低频调度之上，加入：

- 盘中指标：1／5 分钟收益、分钟 MA5／MA20、典型价估算 VWAP、成交量比、日内高低点、放量突破前值和相对板块表现；
- 确定性规则：快速上涨、快速下跌、放量突破、低于估算 VWAP 和逐持仓批次固定止损；
- 事件状态机：首次提醒、持续合并、独立冷却、解除、再次触发和数据不足未知；
- 持仓批次：精确人工确认文本、追加审计、归档保留和按交易日历计算 T＋1；
- 日线分析：确认前复权日 K 的 MA20、拐头天数和正式双条件；
- 追溯查询：原始行情 ID、指标快照、规则事件、事件检查、分析运行和输入 SHA-256；
- 独立离线演示：止损、断网恢复、日 K 未确认、后续确认补记和 T＋1 一次跑通。

本阶段仍只使用模拟与回放数据，不连接真实行情，不调用 Ollama 或云端，不执行交易。完整回归为 **99 项测试**。

## 2. 更新包不会动什么

压缩包不包含：

- `.venv`；
- `runtime` 目录和任何 `.db`、`.db-wal`、`.db-shm`；
- `.env` 或真实密钥；
- 桌面旧备份；
- Ollama 的 `blobs`、`manifests` 或其他模型文件。

下面的复制命令只更新程序、测试、文档、示例和演示配置，**不会覆盖 `D:\pandeng\configs\settings.yaml`**。主数据库仍需要在你确认备份后，通过 `init` 命令升级到结构版本 4。

不需要管理员权限，不需要关闭杀毒软件，也不要为整个项目目录设置杀毒排除。

## 3. 解压到新的临时目录

打开普通 PowerShell。假设更新包已经下载到桌面：

```powershell
$Zip = "$HOME\Desktop\盘灯-第三阶段.zip"
$Package = "$HOME\Desktop\pandeng-stage3-$(Get-Date -Format yyyyMMdd-HHmmss)"

Test-Path $Zip
New-Item -ItemType Directory -Path $Package | Out-Null
Expand-Archive -LiteralPath $Zip -DestinationPath $Package

Test-Path "$Package\pandeng\app\cli.py"
Test-Path "$Package\pandeng\indicators\intraday.py"
Test-Path "$Package\configs\analysis-test.yaml"
Test-Path "$Package\docs\第三阶段更新说明.md"
```

预期第一条和最后四条都返回 `True`。

如果第一条是 `False`，说明路径或文件名不一致。先找到实际下载位置，不要继续复制。可以右键压缩包选择“全部解压”，再把 `$Package` 改为实际解压目录。

如果 PowerShell 一直显示 `>>`，通常是引号或括号没有闭合。按 `Ctrl+C` 取消当前未完成命令，再逐行重新输入。

## 11. 为什么演示库不能反复追加

`analysis-demo` 会拒绝两种危险情况：

1. 数据库文件名不是严格的 `analysis-test.db`；
2. 独立库已经有调度轮次或持仓批次。

这样可以防止把模拟持仓写进主库，也能避免两场演示的分钟线、止损事件和日线结论混在一起。

如果只是第一次验收，无需处理。确实需要重跑时，先把**仅演示库**移动到新的桌面备份，再创建新库。以下命令不会碰主库：

```powershell
$DemoBackup = "$HOME\Desktop\pandeng-analysis-demo-$(Get-Date -Format yyyyMMdd-HHmmss)"
New-Item -ItemType Directory -Path $DemoBackup | Out-Null

foreach ($Suffix in @("", "-wal", "-shm")) {
    $File = "D:\pandeng\runtime\analysis-test.db$Suffix"
    if (Test-Path $File) {
        Move-Item -LiteralPath $File -Destination $DemoBackup
    }
}

python -m pandeng.app --config configs/analysis-test.yaml init
python -m pandeng.app --config configs/analysis-test.yaml analysis-demo --session-date 2026-01-07
```

执行前关闭正在使用演示库的命令。不要对 `pandeng.db` 使用这段移动命令。

只有确实要记录自己的持仓时，才使用主配置执行专用命令。新增必须逐字填写：

```text

```

归档必须逐字填写：

```text

```

命令格式：

```powershell

```

这些代码、日期、数量和价格只演示参数格式。程序不会查询真实账户，也不会因行情或模型输出自行新增、归档或修改批次。

## 14. 数据口径速查

| 项目 | 第三阶段口径 |
|---|---|
| 分钟序列 | 09:31～11:30、13:01～15:00，共 240 点；11:30 续接 13:01 |
| 1 分钟收益 | 当前收盘／前一连续交易分钟收盘－1 |
| 5 分钟收益 | 当前收盘／前 5 个连续交易分钟收盘－1，需要 6 个收盘点 |
| 分钟均线 | 当日最近 5／20 根收盘价算术平均 |
| VWAP | 一分钟典型价乘成交量累计估算，不是精确成交额 VWAP |
| 成交量比 | 当前量／此前 20 个开市日同时刻已确认分钟量均值 |
| 日历完整性 | 基线区间逐日有日历；缺中间日期不能用更早日期补足 |
| 相对板块 | 首分钟开盘到目标分钟收盘的收益差；板块分钟必须连续且确认 |
| 放量突破 | 当前收盘严格高于此前 N 根最高点，量比达到阈值；默认 N＝20 |
| 固定止损 | 每个有效批次独立判断；分钟收盘严格低于人工止损价 |
| 数据不足 | 对应字段或快照为未知，不记成无触发 |
| 普通事件 | 独立冷却，默认 1800 秒 |
| 高优先级事件 | 首次立即提醒；持续默认每 900 秒重复；解除后再触发立即提醒 |
| 恢复和回放 | 只写补记，`notified=0` |
| T＋1 | 当日买入可卖 0；首个后续开市日到达后该批次记录数量可卖 |
| MA20 | 最近 20 根已确认前复权日 K 收盘价算术平均 |
| 拐头 | 首个 MA20 未知；下次不下降为 1、下降为 0；之后递增或归零 |
| 正式双条件 | 确认收盘严格高于 MA20，且拐头天数至少 3 |
| 日 K 确认推进 | 价格、量、来源和复权口径不变时，允许经审计从未确认到已确认 |

## 15. 常见报错

### 找不到 `analysis-demo` 等新命令

新程序没有复制完整，或启动目录不对：

```powershell
Set-Location D:\pandeng
Test-Path D:\pandeng\pandeng\analyzer\demo.py
Test-Path D:\pandeng\pandeng\app\cli.py
Test-Path D:\pandeng\pandeng\tests
python -m pandeng.app --help
```

前两条应为 `True`，第三条通常应为 `False`。如果发现多套一层目录，不要直接删除；先移动到新的桌面备份，再按第 6 节复制目录内容。

### 提示 `no such table: analysis_runs` 或结构版本仍为 3

对正在使用的同一份配置执行 `init`：

```powershell
python -m pandeng.app init
python -m pandeng.app --config configs/analysis-test.yaml init
```

第一条针对主库，第二条针对独立分析演示库。不要在未备份、未跑通测试时反复操作主库。

### `analysis-demo` 拒绝数据库

如果提示只能使用 `analysis-test.db`，说明 `--config` 指向了主配置或回放配置。改用：

```powershell
python -m pandeng.app --config configs/analysis-test.yaml analysis-demo --session-date 2026-01-07
```

如果提示已有演示记录，这是防覆盖保护。参考第 11 节备份旧演示库，不要删除主库。

### 成交量比显示 `None`

常见原因：

- 没有此前 20 个明确开市日；
- 基线区间缺少周末、休市日或某个中间日期的日历记录；
- 某个历史同时刻分钟缺失或未确认；
- 历史同时刻平均成交量为 0。

这些情况下保持未知是安全行为。不能用更早的数据悄悄补足。

### 相对板块表现显示 `None`

未配置 `sector_code` 时会未知。配置后，板块当日分钟缺失、未确认、首分钟开盘无效或序列不连续，也会未知。默认第三阶段演示没有配置板块，因此该字段未知不影响止损验收。

### 收盘后正式日线信号仍是未知

先检查日 K 是否 `confirmed=true`。收盘本身不代表日 K 已确认。独立演示会先展示未确认隔离，再通过受审计的单向确认推进生成回放补记。不要直接修改数据库把未确认记录伪造成当时实时信号。

### 提示同一目标时间输入哈希变化

同一代码、模式和目标时间的原始输入已经变化。程序拒绝把两份不同输入当成同一次幂等执行。保留输出，检查数据质量记录和来源分钟，不要删除旧分析后强行重跑。

### `No module named 'yaml'` 或 `No module named pytest`

通常是虚拟环境没有启用：

```powershell
Set-Location D:\pandeng
Set-ExecutionPolicy -Scope Process Bypass
.\.venv\Scripts\Activate.ps1
python -c "import sys; print(sys.executable)"
```

确认路径指向 `D:\pandeng\.venv`。不要为了排错新建另一套虚拟环境。

### 测试不是 99 项

可能混用了旧测试和新程序，或复制时多套一层。检查：

```powershell
Test-Path D:\pandeng\tests\test_intraday.py
Test-Path D:\pandeng\tests\test_rules.py
Test-Path D:\pandeng\tests\test_analysis_demo.py
Test-Path D:\pandeng\pandeng\tests
```

前三条应为 `True`，最后一条通常应为 `False`。如果仍不通过，保留完整输出并暂停，不重置数据库。
