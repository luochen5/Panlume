# 盘灯手动复盘与云端门控 C4 更新说明

## 一、这次完成了什么

C4 以 C3 完整源码为基线，新增并验收以下能力：

1. 摘要事实层的 VWAP 统一为四位小数，提示词、严格校验和固定模板使用同一个展示值；原始指标快照与规则计算不被回写。
2. 分钟记录只允许在 OHLC、成交量、来源和复权口径完全不变时，从 `confirmed=false` 单向推进为 `true`，同时保存推进前后审计。价格变化、来源变化、复权口径变化和 `true → false` 回退都拒绝覆盖。
3. 新增 `review-daily`：手动整理指定交易日和股票的已保存证据，只写 `review_runs`。它不重新计算指标，不修改行情、规则、提醒频率、日线结论或持仓，也不调用 Ollama 或云端。
4. 新增 `review-status`：只读查看本地复盘、输入 SHA-256 和云端调用审计。
5. 新增 `cloud-review`：仅在逐字确认、云端总开关、`daily_review` 白名单、API Key 配置状态和本地复盘存在等条件全部满足时，对指定本地复盘执行一次 OpenAI 兼容请求。每个本地复盘最多一条云端调用审计，成功和失败都不会自动重试。
6. 数据库结构升级为版本 6，新增 `review_runs` 和 `cloud_review_calls`。版本 4 和版本 5 都在数据库副本上完成升级测试，原文件、旧行情、旧摘要、人工持仓和审计保持原样。

项目只用于公开信息处理、个人研究记录和软件学习，不连接外部账户，不执行外部操作。程序不自动下单，不承诺收益。真实持仓只能由用户手动确认更新，模型无权修改。本地模型只负责摘要，不能修改原始数据和程序结论。敏感配置继续通过环境变量管理。

C4 的安装、自动化测试和离线复盘演示不请求真实行情、真实 Ollama 或真实云端。云端测试使用模拟客户端、本机临时 HTTP 服务和 dummy key。

## 二、尚未完成的真实能力

以下事项不能因为 C4 离线测试通过就视为已经完成：

- 真实分钟闭合规律仍需盘中双探针证据；重叠一致不会自动生成确认边界。
- 真实分钟尚未接入现有自动轮询器。
- 腾讯前复权日线和覆盖 2026 年的可靠交易日历仍需分别实测。
- 修复后的 VWAP 摘要已通过离线严格校验，真实 Ollama 尚未重新实测。
- 真实云端服务尚未请求，C4 不验证任何服务商账号、额度、权限或实际模型质量。
- 是否把真实服务数据写入主库，仍需用户另行明确确认。
- EXE、Logo、发布、备份恢复和一键卸载在核心功能冻结后收尾。

## 九、云端门控的准确含义

默认主配置继续保持：

```yaml
models:
  cloud:
    enabled: false
    base_url: ""
    model: ""
    event_whitelist: []
```

`review-daily` 没有云端客户端调用路径。即使配置中云端和 Ollama 都已启用，本地复盘也不会自动调用它们。

未来如另行决定测试真实云端，命令形态为：

```powershell
& $Python -m pandeng.app cloud-review --review-id 1 --confirmation "确认对指定本地复盘执行一次云端请求并保存审计"
```

这只是命令说明，不是本次验收步骤。不要现在为了测试而购买服务或填写真实密钥。真实请求前仍需当次确认服务商、接口地址、模型、复盘编号、输入内容、预计请求数和费用；本次安装及既有真实行情授权不能沿用为云端授权。

门控按以下顺序执行：

1. 确认文本逐字一致；
2. 云端总开关开启；
3. 白名单包含 `daily_review`；
4. API Key 已配置；
5. 指定本地复盘存在；
6. 该复盘没有既有云端调用审计；
7. 请求大小不超过安全上限，本地输入不包含当前 API Key。

前七项任一不满足都在请求前停止。确认、总开关、白名单、密钥配置或复盘存在性检查失败时，不写云端调用审计。只有进入实际调用阶段后才先写 `running` 审计，再执行一次请求。

云端只接收本地复盘文本和其结构化事实，不接收账户、交易凭证或持仓修改权限。结果必须包含“事实：”“推测：”“后续观察：”，空文本、超长文本、缺少部分、交易指令或收益承诺会保存为失败审计，不能成为研究结论。

网络、认证、权限、限流、参数、HTTP、超时和响应格式异常分别分类。失败审计保留错误类型和耗时，不自动重试。已经成功或已经失败的复盘再次执行 `cloud-review` 都会被拒绝，避免重复收费。若后续证据改变，应先生成新的本地复盘，再另行决定是否请求；不要删除审计绕过限制。

配置加载只检查 `PANDENG_CLOUD_API_KEY` 是否非空，用于门控和配置完整性校验；真实客户端只在进入实际请求前读取当前密钥。请求头中的 API Key 不写入请求审计。保存前还会对响应文本、原始响应审计、模型名和错误消息执行当前密钥脱敏。`.env.example` 只是空白模板，程序不会自动加载 `.env`。

## 十、常见错误与处理

### 1. 提示“数据库结构版本必须为 6”或“升级到结构版本 6”

对当前正在使用的同一份配置运行：

```powershell
& $Python -m pandeng.app --config 你的配置.yaml init
```

不要在不明路径下随意初始化。主库升级前先确认备份。独立演示使用 `configs/review-test.yaml`。

### 2. `analysis-demo` 提示已有记录、拒绝覆盖或追加

这是隔离保护。不要删除数据库。已有演示可直接使用 `review-daily` 和 `review-status`；确需重新做新鲜演示时，先正常退出，把整个旧库及可能存在的 `-wal`、`-shm` 一起移到新的备份目录。

### 3. 本地复盘显示 `unknown`

查看报告中的日历、分钟确认数、质量错误、指标快照和日线结论。缺数据、质量冲突、日 K 未确认或日 K 缺失都应保持未知。本命令只整理证据，不补数、不修复冲突。

### 4. 提示“本地复盘 N 不存在”

先运行 `review-status` 查看实际编号，再使用存在的编号。不要猜测云端请求对象。

### 5. 云端提示总开关、白名单或 API Key 未配置

这些属于默认安全状态，本次离线验收不需要修改。若 YAML 已开启云端但环境变量不完整，配置加载会直接报错，同样不会发起请求。

### 6. 云端命令返回失败，但已经存在审计

进入实际请求后，失败也会保存审计，这是预期行为。用 `review-status --review-id N` 查看错误分类。重复执行不会补发请求。

### 7. PowerShell 显示 `>>`

通常是引号或括号没有闭合。按 `Ctrl+C` 取消当前未完成输入，再整块复制命令。不要反复按回车尝试补齐不理解的结构。

### 8. `Activate.ps1` 被执行策略拦截

继续直接调用 `D:\pandeng\.venv\Scripts\python.exe`，不需要激活虚拟环境，也不要修改系统执行策略。
