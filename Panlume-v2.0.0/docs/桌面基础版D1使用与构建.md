# Panlume 盘灯 v0.1.0 桌面基础版 D1

## 1. 本版交付范围

D1 在 C4 核心之上增加 Tkinter 桌面窗口，保留原有 CLI、数据库结构版本 6 和离线测试。桌面部分包含：

- 浅色与深色主题，主题选择会保存；
- `F11` 全屏、`Esc` 退出全屏；
- 最多五只观察股票的清单编辑；
- 60、300、600 秒档位及 60～3600 秒自定义频率；
- Ollama 模型、超时、摘要触发、输出偏向和调试记录偏好；
- 本机 Ollama 健康检查，只读取 `/api/tags`；
- 独立离线演示，复用 C4 确定性核心；
- SQLite 在线备份、完整性检查、空间统计和保守清理；
- 版本、构建类型、运行平台与诊断摘要；
- Windows PyInstaller、便携 ZIP 和 Inno Setup 构建脚本。

桌面真实行情观察、真实摘要和自动轮询尚未接入。观察清单与模型偏好目前只保存设置，不会悄悄启动真实任务。真实前复权日线、可靠交易日历和新浪备用分钟仍待独立验证。

项目只用于公开信息处理、个人研究记录和软件学习，不连接外部账户，不执行外部操作。

真实持仓只能由用户手动确认更新，模型无权修改。

本地模型只负责摘要，不能修改原始数据和程序结论。

敏感配置通过环境变量管理，并提供示例文件。

## 3. 安全地解压

建议把 D1 解压到一个新目录，例如：

```text
D:\pandeng-d1
```

不要覆盖 `D:\pandeng` 中的个人 YAML、主数据库、虚拟环境或备份。D1 桌面默认也不读取旧的 `D:\pandeng\runtime\pandeng.db`。

压缩包采用平铺结构，解压后应能在目录根部看到：

```text
desktop_launcher.py
requirements-build.txt
packaging\Panlume.spec
packaging\Panlume.iss
scripts\build-windows.ps1
scripts\build-installer.ps1
pandeng\desktop\assets\pandeng.ico
```

## 4. 直接从源码启动（可选）

需要 64 位 Python 3.12 或更高版本，并且 Python 安装时包含 Tcl/Tk 与 `tkinter`。当前项目已经在 Python 3.14 环境工作。

```powershell
Set-Location D:\pandeng-d1
py -3.14 -m venv .venv-desktop
& .\.venv-desktop\Scripts\python.exe -m pip install -r requirements.txt
& .\.venv-desktop\Scripts\python.exe desktop_launcher.py
```

如果 `py` 不可用，可以把第一行中的 `py -3.14` 换成现有 Python 的完整路径。直接调用虚拟环境 Python，不需要激活脚本或管理员权限。

首次启动只创建桌面个人数据库和目录，不请求真实行情，不生成模型文本，不访问云端。

## 5. 在 Windows 构建文件夹版 EXE 与便携 ZIP

### 5.1 一键构建

在源码根目录打开 PowerShell：

```powershell
Set-Location D:\pandeng-d1
& .\scripts\build-windows.ps1
```

脚本会：

1. 检查 64 位 Python 与 Tkinter；
2. 创建独立的 `.venv-build`，不改动原项目 `.venv`；
3. 安装 `requirements-build.txt` 中的构建与测试依赖；
4. 运行完整测试；
5. 用 PyInstaller 6.22.3 构建 `onedir` 文件夹版；
6. 检查数据库结构、演示配置和 Logo 是否打入；
7. 生成带 `panlume.portable` 标记的便携 ZIP 和 SHA-256。

构建依赖需要通过网络下载一次。这个下载发生在构建阶段，不代表桌面启动会联网。

如果 PowerShell 阻止本地脚本，可以只对本次进程使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-windows.ps1
```

该命令不会写入持久执行策略。也可以先审查脚本内容再运行。

如需显式指定 Python：

```powershell
& .\scripts\build-windows.ps1 -PythonPath "D:\pandeng\.venv\Scripts\python.exe"
```

首次构建不建议跳过测试。熟悉流程后才使用 `-SkipTests`，跳过的结果不能计入完整验收。

### 5.2 构建产物

```text
dist\Panlume\Panlume.exe
dist\Panlume-v0.1.0-portable-windows-x64.zip
```

文件夹版必须保留整个 `Panlume` 目录，包括 `_internal`。不能只复制 `Panlume.exe`。`onedir` 方案启动较快，也避免每次运行都把全部文件解压到临时目录；杀毒是否误报仍取决于实际环境和厂商判断。

## 6. 构建当前用户安装版

先安装 Inno Setup 6。可以从其官方页面获取：`https://jrsoftware.org/isinfo.php`。安装 Inno Setup 本身时也可选择当前用户方式，不需要为了盘灯使用管理员账户。

随后执行：

```powershell
Set-Location D:\pandeng-d1
& .\scripts\build-installer.ps1
```

如果没有找到 `ISCC.exe`，显式传入路径：

```powershell
& .\scripts\build-installer.ps1 -InnoSetupPath "C:\Users\你的用户名\AppData\Local\Programs\Inno Setup 6\ISCC.exe"
```

输出：

```text
dist\Panlume-v0.1.0-setup-windows-x64.exe
```

安装版默认位置：

```text
%LOCALAPPDATA%\Programs\Panlume
```

安装程序使用 `PrivilegesRequired=lowest`，仅安装到当前用户目录。标准卸载入口所需的少量信息写入当前用户卸载项，不写系统级卸载信息、开机启动项或驱动。桌面快捷方式默认不勾选，由用户自行选择。

## 7. 个人数据位置与隔离

| 使用方式 | 默认个人数据位置 |
|---|---|
| 源码直接启动 | Linux 为 `~/.local/share/Panlume`；Windows 为 `%LOCALAPPDATA%\Panlume` |
| 安装版 | `%LOCALAPPDATA%\Panlume` |
| 便携版 | 与程序 `Panlume` 文件夹同级的 `PanlumeData` |
| 设置 `PANDENG_DATA_DIR` 后 | 该环境变量指定的独立目录，优先于其他规则 |

个人目录包含：

```text
config\desktop-settings.json
data\pandeng.db
runtime\analysis-demo\analysis-test.db
backups\
audits\
logs\
```

便携 ZIP 的典型结构：

```text
Panlume\
  Panlume.exe
  _internal\
  panlume.portable
PanlumeData\
README-portable.txt
```

`PanlumeData` 在首次运行后创建。请先完整解压便携 ZIP，再运行其中的 EXE。`panlume.portable` 只负责标记便携模式，安装版不会包含它。

桌面 JSON 设置与原 CLI 的个人 YAML 分开。桌面不会重写旧 YAML，也不会把离线演示记录写进旧主库。

## 8. 备份、清理与升级

### 备份

“数据管理”页中的“创建数据库备份”使用 SQLite 在线备份，完成后执行完整性检查。目标文件必须不存在，程序不会覆盖旧备份。升级、安装新版本或手动整理目录前，先创建一个单独备份。

### 清理

清理流程为“预览→确认→重新校验→事务删除”。当前只处理超过保留天数的旧 `minute_bars` 与旧 `run_logs`。

以下内容继续保留：

- 前复权日线与交易日历；
- 人工复盘与持仓；
- 重要审计；
- 被最新指标快照或来源列表引用的分钟；
- 已有人工复盘对应交易日与股票的分钟证据。

预览带有数据指纹。数据或保留设置改变后，旧预览不能执行。清理完成后不自动 `VACUUM`，因此文件大小不一定立即下降。

D1 默认操作的是新的桌面个人库。不要在未确认路径时把旧主库复制进来做清理实验。

### 升级

本版没有自动更新。后续安装新版本前：

1. 在旧版本“数据管理”页创建备份；
2. 确认备份文件位于个人目录之外或已经另行复制；
3. 再运行新安装包；
4. 启动后核对结构版本、观察清单与研究记录。

正常卸载和覆盖安装默认不动 `%LOCALAPPDATA%\Panlume`。使用自定义 `PANDENG_DATA_DIR` 时，升级脚本也不会主动查找或删除该目录。

## 9. 卸载与删除个人数据

安装版可通过 Windows“设置→应用→已安装的应用”或标准卸载入口移除。

卸载默认保留个人数据库、配置、备份和研究记录。交互式卸载结束后会单独询问是否删除 `%LOCALAPPDATA%\Panlume`，默认按钮为“否”。只有明确选择“是”才尝试删除该目录。静默卸载不弹出选择，也不会删除个人数据。

便携版没有卸载写入口。删除便携程序目录即可移除程序，`PanlumeData` 仍会保留。若要删除便携个人数据，请先备份，再手动处理该目录。

自定义 `PANDENG_DATA_DIR` 指向的目录不属于安装程序已知位置，需要用户自行管理。

## 10. Windows 首轮验收建议

先使用隔离目录，避免验收接触任何旧数据：

```powershell
Set-Location D:\pandeng-d1
$env:PANDENG_DATA_DIR = "D:\pandeng-d1-acceptance-data"
& .\dist\Panlume\Panlume.exe
```

检查：

- 六个页面能打开，中文和 Logo 正常；
- `F11` 与 `Esc` 正常；
- 浅色、深色切换后重启仍保留；
- 股票最多五只，重复代码被拒绝，至少保留一只；
- 60、300、600 与自定义 60～3600 秒设置能保存；
- 页面较小时，鼠标滚轮和右侧滚动条能到达底部按钮；
- Ollama 未启动时，主窗口仍能打开；只有点击健康检查才访问本机 `/api/tags`；
- 离线演示首次生成 8 个调度轮次、14 个分析运行、14 个指标快照、10 个事件通知；第二次只读返回；
- 备份生成新文件并通过完整性检查；
- 空库清理预览为 0，不启用执行按钮；
- “关于”页显示 v0.1.0、结构版本 6 和实际 Windows 平台信息。

结束后清除当前 PowerShell 进程的覆盖变量：

```powershell
Remove-Item Env:PANDENG_DATA_DIR
```

安装版再检查标准卸载入口、默认保留数据和可选删除数据。便携版再检查完整解压、同级 `PanlumeData` 和移动目录后的可用性。无 Python 环境验收应使用没有安装 Python 的测试用户或测试机，不需要卸载日常开发环境。

## 11. 常见问题

### 提示缺少 `tkinter`

重新检查 Python 安装组件，确保 Tcl/Tk 与 `tkinter` 已安装。不要用管理员权限绕过问题，也不需要安装额外 GUI 框架。

### PyInstaller 或依赖下载失败

保留最后一段真实错误，先区分网络、权限、Python 版本和依赖问题。不要连续重复构建，也不要关闭杀毒软件。

### 杀毒或 SmartScreen 提示

本学习构建没有代码签名证书，可能出现未知发布者提示。只运行自己从已核对源码构建的文件，并核对 SHA-256。若被拦截，记录厂商、病毒库版本和文件哈希后排查，不设置大范围目录排除。

### 安装脚本找不到 Inno Setup

使用 `-InnoSetupPath` 传入实际的 `ISCC.exe` 路径。脚本不会自动下载或安装额外程序。

### 个人目录无法写入

改用一个明确可写的 `PANDENG_DATA_DIR` 隔离目录，检查磁盘与文件夹权限。无需用管理员身份运行整个桌面程序。
