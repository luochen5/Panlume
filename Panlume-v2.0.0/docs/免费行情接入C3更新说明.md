# 盘灯免费行情接入 C3 更新说明

C3 在 C2 完整源码上增加“明日盘中双探针”和独立离线双探针演示。真实探针固定请求两次东方财富公开一分钟数据，间隔 300 秒，自动重试 0 次，并比较两次原始响应的重叠行。数据库结构继续为版本 5，AKShare 仍固定为已实测的 1.20.65，不新增 YAML 轮询配置键。

项目只用于公开信息处理、个人研究记录和软件学习，不连接外部账户，不执行外部操作。程序不自动下单，不承诺收益。真实持仓只能由用户手动确认更新，模型无权修改。本地模型只负责摘要，不能修改原始数据和程序结论。敏感配置继续通过环境变量管理。C3 真实与离线专用配置均关闭 Ollama 和云端。

## 一、当前完成范围

- 新命令 `akshare-live-probe`：用户当次逐字确认后，才执行两次真实公开分钟请求。
- 两次请求固定间隔 300 秒，自动重试 0 次，两次均显式使用 `confirmed_through=None`。
- 第一次请求失败：不等待、不执行第二次；第二次失败：保留第一次结果，不产生第三次请求。
- 等待期间按 `Ctrl+C`：保留第一次已提交数据和审计，第二次不补发，命令行退出码为 130。
- 自动比较两次原始行：重叠一致、重叠内容变化、第一次有而第二次消失、第二次新增、完全无重叠。
- 比较结果只作为证据，不自动生成分钟确认边界，不修改已有分钟内容。
- 新命令 `eastmoney-probe-fixture-demo`：用保存样本离线执行同一双探针流程，不联网、不导入 AKShare、不实际等待。
- 离线演示只写 `runtime/akshare-probe-fixture/akshare-live-test.db`，不会复用已有 `runtime/akshare-live-test.db`。
- 已增加跨日回归：独立库已有 2026-11-17 的 240 条分钟时，可继续写入次日两轮模拟响应，前一日 15:00 与次日 09:31 不会被误判为当日缺口。
- 当前全量离线自动化测试为 261 项。

尚未完成的部分保持不变：真实双探针尚未在盘中执行；分钟确认推进尚未实现；真实分钟尚未接入自动轮询；腾讯前复权日线和可靠交易日历尚未接入；VWAP 摘要四位小数统一问题尚未修改。现有轮询器启动时需要交易日历，收尾时需要前复权日 K，因此本阶段没有把只有分钟能力的适配器强行塞入轮询器。

## 九、如何解读重叠比较

| 字段或状态 | 含义 | 后续处理 |
| --- | --- | --- |
| `unchanged` | 至少有一个重叠点，所有重叠原始行一致，且第一次的行没有在第二次消失 | 可作为稳定性证据；仍需结合目标分钟和更多样本决定确认边界 |
| `changed` | 有重叠原始行内容变化，或第一次出现的行在第二次消失 | 查看 `changed_times` 与 `missing_in_second`，停止自动确认和后续规则分析 |
| `no_overlap` | 两次响应完全没有共同时间点 | 不推断分钟闭合，保留审计并检查请求范围与上游行为 |
| `new_in_second` | 第二次新增的时间点 | 可与 `unchanged` 同时出现；单纯新增不代表重叠异常 |
| `changed_times` | 同一时间点的规范化原始行哈希不同 | 第二批次会产生 `conflicting_duplicate`，旧数据库内容不被覆盖 |
| `missing_in_second` | 第一次存在、第二次响应中消失的时间点 | 这是上游响应差异记录，不是程序删除了数据库分钟 |

即使两次响应全部重叠一致，也不能仅凭这一组样本宣布“前一分钟必然闭合”。后续需要结合两次实际请求时刻、目标分钟、变化位置和更多低频证据选择保守 `confirmed_through`。C3 不会自动完成这一步。

如果第二次重叠分钟内容变化，第二次新增的其他分钟仍可入库，但冲突行会拒绝覆盖，并留下质量错误；CLI 会显示“至少一次入库存在质量异常”。此时应保存输出和审计，不继续把数据用于指标或规则。

## 十、失败与中断时的审计状态

| --- | ---: | --- | --- |
| 确认文本错误、主库文件名、模型未关闭或无效双请求窗口 | 0 | 不开始 | 第一次请求前停止；确认文本与窗口前置失败不创建探针审计 |
| 第一次网络失败 | 1 | 不等待，不执行第二次 | 汇总 `failed`，无入库批次，保留失败审计 |
| 第二次超时或网络失败 | 2 | 不产生第三次 | 汇总 `failed`，第一次数据和请求审计保留 |
| 等待期间 `Ctrl+C` | 1 | 第二次不补发 | 汇总 `interrupted`，第一次保留，第二份请求审计文件不存在 |
| 两次完成、入库正常 | 2 | 正常结束 | 汇总 `completed`，比较结果完整 |
| 两次完成、出现入库质量异常 | 2 | 正常结束但需停止分析 | 汇总 `completed_with_quality_errors`，冲突可追溯 |

真实错误分类沿用 C2：`dependency_missing`、`dependency_version`、`parameter_error`、`network_error`、`authentication_failed`、`permission_denied`、`timeout`、`empty_data`、`rate_limited`、`http_error`、`request_failed`、`response_format`、`response_scope`。无法从异常取得明确证据时保留 `request_failed`，不猜原因。

AKShare 高层接口没有向本适配器暴露单次硬超时参数，YAML 中的 `monitor.fetch_timeout_seconds: 20` 不能被当作该调用的强制 20 秒上限。遇到超时、限流、权限或验证码等访问限制时，不自动重试，不绕过限制，不通过高频请求或换接口规避。

## 十一、常见问题

### 离线演示是否消耗真实请求次数

不会。它只读取 ZIP 中已有 JSON，请求审计明确标为 `offline_fixture`，真实网络请求为 0，也不导入 AKShare。真实双探针与离线演示使用不同目录的数据库和审计。

### 离线演示提示数据库不是全新

这是防重跑保护。使用 `data-status` 和 `data-audit` 查看旧结果，不要删除数据库。实时独立库允许跨日继续写入，离线演示库则固定为一次性新鲜验收，两者规则不同。

### 双探针提示当前与五分钟后必须在交易分钟

在第一次请求前调整启动时间即可，不需要修改代码或系统时间。午休、11:26、14:56、收盘后等窗口被故意拒绝。不要为绕过检查而伪造 `session-date`。

### 体检显示 unknown

全部探针分钟显式未确认，交易日历也没有伪造，因此 `unknown` 是安全结果。若同时存在缺口或质量错误，保留输出和审计，停止后续分析。

### PowerShell 把 period 或 adjust 当成命令

这两个是 Python 函数参数，不是独立 PowerShell 命令。只复制本文完整命令，不要单独输入 `period="1"` 或 `adjust=""`。

### 是否需要管理员、激活虚拟环境或关闭杀毒软件

都不需要。继续直接调用 `D:\pandeng\.venv\Scripts\python.exe`，不修改执行策略，不安装驱动，不修改注册表，不设置开机启动，也不要通过大范围杀毒排除目录规避检查。
