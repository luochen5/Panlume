# 盘灯真实行情适配器预备阶段更新说明

> **历史版本说明：**本文记录预备阶段当时的 137 项测试。当前完整版本为真实行情适配器 B，安装与验收请以 `真实行情适配器B更新说明.md` 为准。B 包已包含本文所述代码，不需要先安装预备版。

本包以第四阶段 A 的完整源码为基础，新增真实行情接入前的离线契约、范围防护和增量验收。尚未选择或连接任何真实数据服务商，未新增运行依赖，数据库结构继续保持版本 5。

项目只用于公开信息处理、个人研究记录和软件学习，不连接外部账户，不执行外部操作。本包不会自动下单，不会修改真实持仓，也不会请求真实行情、Ollama 或云端。

## 一、这次完成了什么

1. 新增严格 JSON 行情样例适配器，分别实现原始未复权分钟线、前复权日线和交易日历三个只读接口。
2. JSON 样例必须明确给出 `adjustment` 和 `confirmed`，不能靠程序猜测复权或确认状态。
3. 在既有调度器入库前增加响应范围检查。返回其他股票代码、请求区间外分钟、日线或日历时，本次读取失败并记录状态未知。
4. 单只股票读取异常不影响其他正常股票；范围外记录不会写入 SQLite。
5. 空增量响应不会被当作“数据完整”，连续检查点不会虚假前进。
6. 新增 `adapter-demo`，使用手动时钟连续执行两轮读取，验证第二轮从上次连续检查点之后补数。
7. 演示只允许写入全新的 `runtime/adapter-test.db`，已有业务数据时拒绝覆盖或追加。
8. 全量离线测试由 121 项增加到 137 项。

本次没有修改止损、T＋1、MA20、指标、规则、摘要、持仓或数据库表结构。

## 三、数据流与真实接入位置

当前离线验收的数据流：

```text
本地 JSON 样例
  → MarketDataAdapter 三个只读接口
  → 请求代码与时间／日期范围检查
  → 既有清洗、去重、冲突检查和 SQLite 入库
  → 既有逐股票连续检查点与缺口的未知状态门控
```

以后选定合规数据服务时，新增一个真实适配器，把该服务的字段映射为既有 `MinuteBar`、`DailyBar` 和 `TradingDay`。指标、规则和模型层不需要直接理解服务商的原始字段。

真实适配器仍需完成官方文档核对、授权确认、环境变量凭证、请求限制、字段单位和实际样例核验。本包没有假装完成这些工作。

再次对已有 `adapter-test.db` 执行演示时，程序应拒绝并显示“本次没有覆盖或追加”。不要删除数据库绕过保护。

确需重新验收时，确认没有盘灯程序使用该数据库，再把旧库移动到本次备份：

## 九、常见问题

### 提示“只允许写入文件名 adapter-test.db”

这是主库隔离保护。检查是否忘记在命令中写：

```powershell
--config configs/adapter-test.yaml
```

不要为了通过检查而把主库重命名。

### 提示 JSON 缺少 `confirmed` 或 `adjustment`

这是有意设置的严格契约。真实适配器以后也必须明确映射这两个字段，不能把缺失确认状态默认当成正式日 K，也不能把未知复权数据标成 `qfq`。

### 提示“超出请求闭区间”或“不在本次请求范围内”

受影响读取会记为状态未知，范围外数据不会入库。保留错误和原始请求记录，检查适配器映射及服务商分页、时区和代码格式，不要把错误记录强行改成请求时间。

### PowerShell 出现 `>>` 或大量红色文字

`>>` 通常表示引号或括号没有闭合，可按 `Ctrl+C` 返回后重新复制完整命令。只复制代码块，不要复制 `PS D:\pandeng>`、旧输出或预期结果。

## 十、真实数据服务接入前仍需核对

- 服务条款允许你的个人本地研究、保存方式和使用频率；
- 分钟线、前复权日线和交易日历都有正式接口与字段文档；
- 时间时区、分钟点归属、成交量单位、复权方式和确认状态已经实测核对；
- 历史深度足够补齐断网期间的缺口；
- 凭证只从环境变量读取，不进入 YAML、源码、日志或数据库；
- 请求有超时、频率限制、有限重试和响应范围检查；
- 先用少量股票和独立 `real-data-test.db` 验证，不直接写入主库；
- 数据缺失、冲突、过期或日 K 未确认时继续显示“状态未知”；
- 是否接入主库由你另行明确确认。
