# Panlume 2.0 阶段 1：统一事实包与完整固定模板

## 本阶段完成内容

- 新增版本化统一事实包 `pandeng.fact-package`（结构版本 `1.0`），覆盖实时事件摘要和单票收盘详细分析。
- 事实包包含数据范围、来源、质量、确认状态、价量统计、时间线、指标、规则事件、人工确认持仓、限制和追溯信息。
- 每条规则事件包含事件/规则 ID、名称、状态、首末触发、解除、条件、实际值、阈值、窗口、重复合并、冷却截止和证据 ID。
- 提供稳定 JSON、SHA-256 内容哈希和与原件隔离的模型只读副本；不写入报告生成时间等运行信息。
- 新增数据库只读构建器，复用既有行情、指标、规则和持仓证据，没有建立第二套规则引擎。
- 实时摘要明确事件名称、当前状态、触发依据、实际数值、阈值、窗口、合并、冷却、质量和追溯。
- 单票详细固定模板包含完整程序事实区；无 Ollama 时仍可生成，不设置强制字数下限。
- 新规则检查补存条件表达式、时间窗口、回看参数和冷却秒数。旧记录缺这些字段时保留限制说明，不猜造历史配置。
- 原摘要任务和本地复盘保留旧字段，新增 `fact_package` 部分；历史文本和数据库结构未改写。
- 版本号保持 1.0.0，数据库结构保持 6，未进入阶段 8 发布流程。

## 关键设计说明

1. `FactPackage.canonical_json()` 使用排序键、紧凑分隔符、UTF-8 中文和禁止 NaN 的 JSON；`content_hash()` 只哈希事实内容。
2. 构建器连接启用 `PRAGMA query_only = ON`。测试对构建前后所有表做快照比较，确认零写入。
3. 实时事件的指标/价量范围对准所选提醒时刻，规则生命周期读取当日完整检查记录，避免当前状态与解除证据互相矛盾。
4. 规则数值和结论只来自 Python 已有记录。报告中的条件性解释为固定边界说明，不推断新闻、资金或未来涨跌。
5. 模型提示词继续保留 v1 摘要字段，并附带事实包只读副本；既有工作线程、队列、校验和回退机制保持可用。
6. `review_runs.input_json` 保留 `pandeng.daily-review-input.v1` 和旧字段，同时加入独立版本化事实包，避免破坏旧读取方。
7. 展示层对每个事件只展开证据数量及部分 ID，完整 ID 始终在事实包中，减少重复篇幅不减少底层事实。
