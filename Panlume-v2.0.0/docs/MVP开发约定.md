# 盘灯 MVP 开发约定（修订版）

## 1. 项目边界

盘灯（pandeng）是 Windows 笔记本本地运行的 A 股行情监控、信息整理与摘要工具，也是编程学习项目。仅处理公开行情、个人持仓记录和研究资料；不连接外部账户，不自动下单，不执行外部操作，不承诺收益。第一版不提供网页或复杂 Agent。

模型只负责文字整理，无权修改行情、指标、程序结论或真实持仓。所有指标和规则结论由 Python 确定性计算。

## 2. MVP 范围

支持 5～10 只自选股、模拟一分钟行情、CSV 历史回放、可替换的只读数据适配器、SQLite、盘中指标、固定止损、T+1、前复权日线 MA20、事件合并与提醒频率控制、Ollama 异步摘要、固定模板回退、默认关闭的 OpenAI 兼容云端接口，以及暂停恢复和收盘自动退出。

截至 C1，真实数据服务尚未绑定；后续只考虑具有正式文档、明确服务条款并允许个人本地研究的来源。免费或流行不能替代授权、稳定性和字段准确性检查。适配器预备版本用严格本地 JSON 样例固定三类只读接口的离线契约；真实行情适配器 B 增加只读数据体检和轮询档位提示；真实行情接入 C1 增加 Tushare 虚拟响应映射、09:30 显式排除和原始行追溯。

C2 已增加 AKShare 1.20.65 东方财富公开一分钟适配器，并保存一次收盘后真实公开响应作为离线样本。C2 提供独立离线演示和逐字确认的一次性真实请求入口，默认安装、测试和离线演示均不联网。真实请求固定一次、无自动重试，只写 `runtime/akshare-live-test.db`，完整原始行保存为独立 JSON 审计；这属于应用层响应审计，不冒充原始 HTTP 响应体捕获。真实服务商的长期稳定性、盘中分钟闭合语义、前复权日线和交易日历仍需分别验证。是否接入主库或自动轮询继续由用户另行明确确认。

C3 增加盘中双探针：当次逐字确认后固定请求两次，间隔 300 秒，自动重试 0 次，两次均 `confirmed_through=None`。第一次失败则不等待且不执行第二次；第二次失败保留第一次结果，不产生第三次请求；等待期间 `Ctrl+C` 保留第一次结果并停止。程序自动报告重叠一致、内容变化、第一次有而第二次消失、第二次新增和无重叠，但这些结果只作为证据，不自动生成确认边界。独立离线演示使用保存样本、模拟时钟和 `runtime/akshare-probe-fixture/akshare-live-test.db`，不联网、不实际等待，也不复用实时独立库。

C4 增加确定性本地每日复盘与显式云端门控。本地复盘只读上游证据，按规范化输入 JSON 的 SHA-256 幂等保存到 `review_runs`，不调用 Ollama 或云端，不回写行情、指标、规则、提醒或持仓。`cloud-review` 必须同时满足逐字确认、云端总开关、`daily_review` 白名单、API Key 配置和本地复盘存在等条件；每个本地复盘最多一条调用审计，实际请求一次，成功或失败都不自动重试。云端结果只作研究记录，必须区分事实、推测和后续观察，不得包含交易指令或收益承诺。

## 3. 行情适配器与数据口径

适配器分别提供：

1. 原始未复权分钟行情，用于盘中指标与价格提醒；
2. 前复权历史日 K，用于 MA20 和正式日线信号；
3. 交易日历，用于交易时段和 T+1 判断。

每条数据保存数据来源、复权口径、行情时间和确认状态。模拟器与 CSV 回放也必须提供分钟线、前复权日线和交易日历测试数据。

分钟行情按代码、时间和来源检查缺失、重复、乱序及内容冲突。同一代码和时间出现内容冲突时停止该部分分析。数据过期或缺失时显示“状态未知”，不得记录为“无触发”。单只股票异常不影响其他正常股票。历史回放使用回放时钟，不按当前电脑时间判断过期。

调度器在清洗入库前检查适配器响应范围。明确属于其他股票代码或请求时间／日期闭区间之外的记录，整次读取按失败处理，不能写入 SQLite；格式尚无法解析的记录交给清洗层留下质量审计。空增量响应不能视为完整数据，连续检查点只能根据实际保存且通过质量检查的分钟推进。严格 JSON 契约必须明确提供 `adjustment` 和 `confirmed`，不能把缺失字段默认为未复权、前复权或正式确认。

真实行情适配器 B 的 `data-audit` 只读回看指定交易日截至时刻的数据，连接必须启用 `PRAGMA query_only = ON`，不得补数、修复冲突、计算规则或调用模型。分钟状态分为 `ok`、`price_only` 和 `unknown`：目标分钟有效且确认、无目标分钟质量冲突时，即使历史序列有缺口，也可保留价格线；目标分钟缺失、未确认或有质量冲突时，价格线必须为未知。日 K 的 `confirmed`、`unconfirmed`、`missing`、`unknown` 独立报告，不能反向改写分钟完整性。检查点用于展示，不得单凭缺少调度检查点否定 CSV 已入库的实际分钟。分钟质量错误只统计到 `as_of_time`，更晚错误不得污染较早回看。审计成功执行可以返回 0，数据异常必须在报告正文中明确显示。该回看只描述当前数据库内容，不证明数据在当时已经实时到达。

真实行情接入 C1 只允许人工编写的 `pandeng.tushare-fixture.v1` 离线样例，不得把来源标为真实 Tushare。股票代码与 SH／SZ／BJ 后缀必须无歧义对应；服务商无时区分钟时间按固定 UTC＋8 解释，秒和微秒必须为 0；分钟 `vol` 按股、日线 `vol` 按手换算，换算后必须为股数整数。C1 历史样例中的 09:30 记录必须单列排除，不得改名为 09:31。普通未复权日线不能改名为 qfq；日线 `confirmed` 必须显式提供，C1 虚拟日线固定保持未确认。每条入库数据的 `raw_json.provider_raw` 保留虚拟服务商原始行。真实响应的权限、单位、确认语义、前复权锚点与历史一致性仍须在一次性真实请求中重新核验，不能由离线样例推定。

C2 对 09:30 统一使用中性“09:30 特殊点”名称，不擅自判定其交易阶段。东方财富分钟原始响应必须时间严格递增，重复和乱序均拒绝；常规分钟限制为 09:31～11:30、13:01～15:00，保留 15:00，不制造 13:00。OHLC 和时间完整的零成交量行不得直接删除。`confirmed_through` 必须显式提供，不能因最后一根已经返回就自动确认。请求前检查代码和闭区间；空响应、网络失败、认证失败、权限不足、参数错误、超时、限流和响应格式异常分别记录，真实空数据不得创建入库批次或推进检查点。AKShare 高层接口未向本适配器暴露单次硬超时参数时，不得把 YAML 超时值宣称为实际强制上限。

C3 双探针不判断真实节假日，只能在用户已核实的开市日启动；当前时间与五分钟后的时间都必须落在当日交易分钟内，否则第一次请求也不会执行。汇总审计记录计划与实际请求数、重试数、计划与实际间隔、两次目标分钟、请求审计路径、重叠比较和副作用标记。跨日复用已有独立库时，不得把前一日 15:00 与次日 09:31 误判为当日分钟缺口。C4 已实现分钟确认推进的通用入库能力：只有 OHLC、成交量、来源和复权口径完全不变时，才允许从 `confirmed=false` 单向推进为 `true`，同时更新入库追溯并保存推进前后的信息级质量审计。该能力不会自动生成真实确认边界，真实边界仍需盘中证据和后续显式接入。

## 4. 运行时间、频率和离线功能

自动监测由用户手动启动，默认每 5 分钟检查一次。每次增量获取上次检查以来新增的全部一分钟行情，不能只取最新一条。频率继续使用 `monitor.interval_seconds`，配置限制为 60～3600 秒。推荐显示 60 秒＝1 分钟档、300 秒＝5 分钟默认档、600 秒＝10 分钟档；其他合法值显示为自定义档，不新增 YAML 键或互相覆盖的命令行参数。轮询间隔只改变检查频率，不改变增量补齐、确定性规则或模型事件资格。

只在交易时段执行自动监测，午休不轮询。非交易日或收盘后启动监测时，程序说明状态后退出。终端同时显示最新行情时间与本次检查时间，明确止损提醒可能受到轮询和数据源延迟影响。

收盘后停止新轮询，补取并处理最后一轮可获得的数据，保存事件和检查点，在限定时间内完成已有摘要任务，安全关闭 SQLite 并自动退出。最后行情获取失败时记录数据不完整及失败原因，不无限重试。

非交易时段允许用户手动执行历史回放、本地每日复盘和历史查询，不启动自动实时监测。

## 5. 暂停、恢复与断网

用户暂停时保存最后处理的行情时间、事件状态和检查点，停止安排新任务。继续时先补取可获得的数据、检查缺口，再恢复分析。补跑结果标记为“离线恢复记录”，不能冒充当时的实时告警。

断网时采用有限重试和明确超时，受影响状态显示未知，暂停新的模型分析并保留原始记录。恢复后先补数据并检查连续性。收盘时网络仍不可用，也在记录原因后收尾退出。

## 6. 指标、MA20 与拐头算法

第一版盘中指标为 1 分钟和 5 分钟涨跌幅、成交量比、VWAP、日内高低点、分钟均线和相对板块表现。第三阶段已经固定以下口径：

- 1 分钟收益为当前收盘／前一连续交易分钟收盘－1；5 分钟收益使用当前及此前 5 个连续交易分钟，共 6 个收盘点。
- 11:30 的下一连续交易分钟是 13:01，跨午休的收益仍按交易分钟序列计算。
- MA5 和分钟 MA20 分别为当日最近 5／20 根分钟收盘价算术平均。
- VWAP 使用一分钟典型价 `(high + low + close) / 3` 乘成交量累计估算，不宣称是基于真实成交额的精确 VWAP。C4 在摘要事实层把提示词、严格校验和固定模板中的 VWAP 统一为四位小数字符串，避免长浮点表示导致模型逐字校验失败；原始指标快照和规则计算值不被回写。
- 成交量比使用此前 20 个明确开市交易日同一时刻的已确认分钟成交量均值。最早基线日到当前日前一天必须逐日有交易日历；缺少中间日期时保持未知，不能用更早日期补足。
- 日内高低点取截至目标分钟当日最高 `high` 和最低 `low`。
- 放量突破要求当前收盘严格高于此前 N 根分钟最高点，且成交量比达到阈值；默认 N＝20，不包含当前分钟。
- 相对板块表现为股票与板块从当日首分钟开盘到目标分钟收盘的收益差，单位为百分点；板块当日分钟必须连续且已确认。
- 数据预热不足只让对应字段为未知；目标分钟有效而历史序列有缺口时，只保留当前价格线供固定止损独立判断，完整上下文指标保持未知。目标分钟缺失、未确认或内容冲突时，整份价格线为未知，不得记录为“无触发”。

盘中结果统一标记为“盘中动态”，不得改写正式日 K 结论。

前复权日线 MA20 与拐头规则：

- 只使用已经确认的前复权日 K，以最近 20 根有效日 K 的收盘价计算 MA20。
- 拐头天数只根据相邻两个交易日的 MA20 数值计算，不使用当日最低价、阳线数量或连续上涨天数。
- 当日 MA20 低于前一日 MA20 时，拐头天数立即归零。
- 当日 MA20 不低于前一日 MA20 时，拐头天数在前一日基础上增加一天。
- 历史数据不足或 MA20 序列存在未处理缺口时，拐头状态为未知。
- 正式右侧信号要求确认后的日 K 收盘价严格高于当日 MA20，且拐头天数至少为 3 天。
- 正式信号只能在日 K 确认后生成。
- 测试必须验证 MA20 连续不下降时拐头天数逐日增加，不得以股价最低价替代 MA20。

收盘不等于日 K 已正式确认。收盘时尚未获得确认日 K 的，正式日线结论保持未知；程序可以保存盘中结果并退出。以后手动回放或补数后只能生成补记，不得倒填成当时已确认的实时信号。

## 7. 自选股、持仓批次与风险事件

自选股和阈值保存在 YAML；真实持仓保存在 SQLite，两者分离。持仓只能通过专门命令修改，并要求用户显式确认。模型没有持仓写入权限。

持仓变更按买入批次保存数量、买入日期和用户确认的固定止损信息。多个批次分别计算 T+1 可卖数量。MVP 不自动推断未记录的加仓、减仓或除权变化；记录不完整时要求用户核对。交易日历不足时可卖状态为未知。新增和归档分别使用专用精确确认文本，并追加写入 `position_audit`；归档保留原批次，只让它退出当前持仓计算。部分卖出或录入错误暂按“归档原批次并新增核对后的剩余／正确批次”处理，不直接改数据库；后续如增加 reduce、correct 命令，仍须精确人工确认并追加审计。

当日买入批次可卖数量为 0。买入日后的首个开市日到达后，该批次全部记录数量具备可卖资格。买入日缺失、买入日明确休市、买入日期晚于查询日，或尚未找到首个开市日时中间日历缺失，状态均为未知。已经找到首个开市日后，更晚日历缺失不反转已经获得的可卖资格。

每批有效行情到达后立即检查固定止损，不等待模型。判定口径为目标分钟收盘价小于或等于该批次人工确认止损价，即触及或跌破均提醒。目标分钟有效时，历史分钟缺口不阻止价格线判断；完整上下文指标仍保持未知。目标分钟缺失、未确认或内容冲突时，价格线为未知。止损不等待 VWAP、成交量基线、板块数据或 T+1 日历完整；T+1 未知只影响可卖数量字段。系统只生成风险提醒和状态记录，不执行交易。

高优先级事件首次触发时立即提醒；持续处于同一触发状态时合并保存每次检查记录，并按独立频率提醒；状态解除后再次触发时重新立即提醒。高优先级事件不适用普通冷却，但也不能每次轮询都刷屏。具体独立频率在规则阶段配置和测试。

## 8. 普通事件与模型频率

正常波动只保存必要快照，不调用模型；轻微异常仅记录本地日志。普通规则事件先显示固定告警，再按配置决定是否生成本地摘要。同一普通事件在冷却期内合并，不重复调用云端。第三阶段普通规则为 `rapid_rise`、`rapid_fall`、`volume_breakout` 和 `below_vwap`，默认普通冷却 1800 秒，高优先级固定止损持续提醒间隔 900 秒。触发、解除和数据不足分别保存为 `is_active=1`、`0` 和 `NULL`；未知检查不能解除已有活动事件。

每日复盘由用户手动启动，默认本地生成。云端默认关闭，白名单默认为空；启用白名单模式也必须显式打开云端功能，手动调用需要当次确认。普通行情和默认复盘不调用云端。

## 9. Ollama 与云端

本地默认使用 Ollama API 调用 `deepseek-r1:14b`，输入仅为触发事件、对应行情和 Python 已计算指标。最终摘要只设置合理长度上限，不强制最低字数，保留代码、完整行情时间和关键数值，不猜测新闻原因，不补充输入外数据。R1 思考段与最终摘要分离，思考文本只进入模型调用审计，未闭合或错位标签触发模板回退。

Ollama 同时最多一个任务，队列有容量上限，初始请求超时 60 秒。队列满时立即保存固定模板，不发起额外模型请求。摘要不阻塞行情、规则或止损。输出校验失败、超时或服务不可用时回退固定模板，原始结构化告警始终保留。SQLite 连接按操作和线程独立创建、关闭；异常退出后恢复未完成任务，已完成任务保持原结果，不再重跑；收尾等待有上限，迟到结果不能覆盖模板。盘灯不强制结束用户可能正在使用的 Ollama 进程。

本机曾有约 20 秒生成千字文本的个人实测，仅作设计参考，不作为项目性能验收指标。模型加载、耗时、显存、内存和温度在第四阶段单独实测。

云端日常事件摘要只接收已筛选事件、关键指标、近期状态和本地摘要；C4 的显式 `cloud-review` 只接收指定本地复盘文本及其结构化事实。结果区分事实、推测和后续观察条件，不生成交易指令或收益承诺。密钥只从环境变量读取，不写入 YAML、日志或数据库。配置加载只记录密钥是否非空；真实客户端仅在实际请求前读取当前密钥并放入内存中的 Authorization 请求头。请求审计不保存请求头，响应文本、原始响应审计、模型名和错误消息落库前对当前密钥脱敏；本地复盘输入包含当前密钥时在写审计和请求前拒绝。

## 10. 存储、追溯与安全

SQLite 后续保存原始行情、质量问题、指标快照、事件及提醒记录、持仓批次与人工变更、本地摘要、模板回退、云端结果、复盘、模型调用和运行检查点。第三阶段追溯关系为：原始行情 ID → 指标快照 ID → 规则事件 ID → 事件检查 ID；`analysis_runs` 同时保存分析模式与输入 SHA-256。结构版本 5 新增摘要任务、摘要结果和模型调用表，每个实时事件检查最多一条摘要任务，可从摘要任务追溯事件检查与指标快照，不允许模型回写上游数据。结构版本 6 新增 `review_runs` 和 `cloud_review_calls`：本地复盘以 `(session_date, stock_code, input_hash)` 唯一约束幂等保存，云端审计以 `review_id` 唯一约束限制每个本地复盘最多一次调用。版本 4 到 6、版本 5 到 6 的升级均在数据库副本上留下自动化测试，原文件及旧行情、分析、摘要、人工持仓和审计保持不变。

同一 `(session_date, stock_code, analysis_mode, target_time)` 的盘中分析幂等跳过；输入哈希变化时报告数据冲突。离线恢复和回放只写补记，`notified=0`，不能冒充当时实时告警。日 K 只有在价格、成交量、来源和复权口径完全不变时，才允许经审计从 `confirmed=false` 单向推进为 `true`，不能借确认推进修改价格。

模型日志保存输入、输出、时间、耗时、错误及接口实际返回的 token 用量；未返回时记录未知。应用日志可按大小轮换，原始记录默认不静默删除。

项目使用 Python 虚拟环境，不需要管理员权限，不安装驱动，不修改注册表，不设置开机启动，不执行任意系统命令。依赖保持精简，网络与模型请求均有超时，退出时安全保存检查点并关闭数据库。
