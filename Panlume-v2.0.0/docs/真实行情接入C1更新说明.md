# 盘灯真实行情接入 C1 更新说明

C1 在真实行情适配器 B 的完整源码上增加 Tushare 虚拟响应映射、独立离线演示和 55 项测试。当前全量测试为 **214 项**。数据库结构继续保持版本 5，没有新增运行依赖。

本阶段没有 HTTP 客户端，不读取 Tushare Token，不请求真实行情、真实 Ollama 或云端。虚拟样例只能验证字段转换和入库链路，不能证明用户拥有分钟权限，也不能证明真实实时数据可用。

项目只用于公开信息处理、个人研究记录和软件学习，不连接外部账户，不执行外部操作。程序不自动下单，不承诺收益。真实持仓只能由用户通过专用命令显式确认更新；模型无权修改行情、指标、规则结论或持仓。银河证券仍只考虑正式授权的只读行情 API，不登录交易功能，不查询账户资产或订单。

## 一、这次完成了什么

1. 增加服务商响应的通用校验：10 MB 上限、UTF-8 JSON、根节点类型、6 位 A 股代码与 SH／SZ／BJ 后缀、固定 UTC＋8 时间、YYYYMMDD 日期和成交量单位。
2. 增加 Tushare 成功响应的 `code`、`msg`、`request_id`、`data.fields` 和 `data.items` 检查，字段缺失或行长度不一致时拒绝映射。
3. 分钟 `vol` 明确按股处理；日线 `vol` 明确按手处理，乘 100 后必须为整数股，不能静默四舍五入。
4. 官方分钟样例中出现的 09:30 记录单列为开盘集合竞价排除项，不改写为 09:31。
5. 分钟确认状态由显式 `confirmed_through` 边界计算；晚于该边界的记录保持未确认。
6. 日线必须显式声明 `adjustment="qfq"` 和布尔值 `confirmed`。普通日线字段不能改名为前复权日线。
7. 入库记录的 `raw_json.provider_raw` 保存虚拟服务商原始行，`provider_request_id` 保存虚拟请求标识。
8. 新增 `provider-fixture-demo`，在独立 `real-data-test.db` 中走通三类接口、范围防护、清洗入库和只读体检。
9. `.env.example` 增加空白 `PANDENG_TUSHARE_TOKEN=` 占位；当前代码不会读取该变量。
10. 全量测试从 159 项增加到 **214 项**。

本次没有修改止损、T＋1、MA20、指标、规则、摘要、持仓、数据库表结构或个人默认轮询间隔。

## 三、数据流与关键口径

```text
人工编写的虚拟 Tushare 响应
  → 响应大小、字段、类型和行长度检查
  → 股票代码、UTC＋8 时间、成交量单位映射
  → 09:30 开盘集合竞价单独排除
  → 既有代码与请求闭区间防护
  → 既有清洗、去重、冲突检查
  → 独立 real-data-test.db
  → 既有 data-audit 只读体检
```

| 项目 | C1 处理 |
| --- | --- |
| 股票代码 | `600000.SH` → `600000`；代码段与后缀不一致时拒绝 |
| 无时区分钟时间 | 明确按 UTC＋8 解释，不读取 Windows 本地时区 |
| 整分钟 | 秒和微秒必须为 0 |
| 09:30 | 记录到排除项，不进入连续竞价分钟，不改名 |
| 分钟成交量 | 按股，必须为非负整数 |
| 日线成交量 | 按手，乘 100 后必须得到整数股 |
| 分钟复权 | 显式 `adjustment="none"` |
| 日线复权 | 只接受显式 `qfq` |
| 日线确认 | 虚拟样例固定 `confirmed=false`，体检单独显示未确认 |
| 原始行追溯 | 保存在 `raw_json.provider_raw`，不包含 Token |

离线样例沿用了当前官方文档中可见的字段和时间样例。真实接入前仍要核验实际响应，尤其包括 09:30 的业务含义、分钟是否未复权、日线前复权锚点、历史一致性和日 K 最终确认条件。

## 九、常见问题与防重跑

### 提示“数据库尚未初始化”

先确认命令中带有 `--config configs/real-data-test.yaml`，再执行：

```powershell
python -m pandeng.app --config configs/real-data-test.yaml init
```

### 提示“只允许写入文件名 real-data-test.db”

这是主库隔离保护。恢复使用专用配置，不要把主库改名来绕过：

```powershell

```

### 提示“只使用全新的 real-data-test.db”

演示已经运行过，或该库存在其他业务记录。程序没有覆盖或追加。先使用 `data-audit` 查看；确需重跑时按第七节备份移动旧测试库。

### 提示“Ollama 和云端均关闭”

专用 YAML 必须保持两个开关为 `enabled: false`。不要为离线演示启动模型，也不要开启云端。

### 提示配置根节点存在无法识别的配置项

检查是否完整复制了本包的 `configs/real-data-test.yaml`。当前程序使用 `rules`、`summary`、`storage.database` 和 `models.cloud.event_whitelist` 等既有键，不接受旧草案中的 `analysis`、`database_path` 或 `allowlist`。

### 提示找不到离线样例、字段缺失或行长度不一致

在 `D:\pandeng` 根目录运行命令，并检查：

```powershell
Test-Path D:\pandeng\examples\provider_fixtures\tushare\offline_responses.json
```

不要从真实账户或未知网站复制数据填入样例，也不要为通过测试而删除必要字段。文件损坏时从更新包重新复制该虚拟样例。

### 返回 0 但报告存在未知或质量错误

返回 0 表示体检命令执行成功，数据健康程度以正文为准。本次新鲜虚拟库应全部为 `ok`；如果不是，保留输出并停止后续真实接入。

### PowerShell 出现 `>>`

通常是引号或括号没有闭合。按 `Ctrl+C` 取消当前未完成输入，再逐行复制完整代码块。不要粘贴旧输出或 PowerShell 提示符。

### 权限错误、超时和无数据的区别

未来真实请求中，认证失败、权限不足、超时和参数错误都需要明确报告，不能当成“没有行情”。C1 不会发起这些请求，也不会用离线成功掩盖真实权限问题。

## 十、真实服务商仍需核验的项目

### Tushare

用户只需查看本人权限中心和官方文档，不需要把 Token 发给助手，也不要为了推进项目先行购买。

- A 股分钟 RT 是否已开通、是否有官方试用、可用频率和并发限制；
- A 股历史分钟是否已开通，历史深度是否满足成交量基线和回放需要；
- `rt_min` 与 `rt_min_daily` 的 09:30 记录含义、分钟收盘口径、成交量单位和未复权口径；
- 前复权日线的官方获取方式、复权锚点、历史一致性和成交量单位；
- 日 K 何时可视为最终确认，是否会更正；
- `trade_cal` 的本人权限、返回字段和交易所范围；
- 服务条款是否允许个人本地保存、研究和故障排查。

官方页面价格具有时效性，购买前重新查看。拥有账户、积分或普通日线权限不等于拥有分钟权限。

### 银河证券

继续通过银河官网客服渠道或客户经理确认：

- 普通个人账户能否申请正式只读行情 API；
- 是否提供一分钟和历史分钟数据、前复权日线、交易日历；
- 申请条件、费用、频率、历史深度和本地保存规定；
- 是否必须安装特定客户端，是否有官方 Python 文档；
- 能否只使用行情权限，完全不登录交易功能。

证券账户存在不等于行情 API 权限已经开通。官方资料到位前不安装 QMT、不购买服务、不创建银河适配器，也不使用屏幕识别、模拟点击、破解客户端或未授权接口。
