# 盘灯免费行情接入 C2 更新说明

C2 在 C1 完整源码上增加东方财富一分钟适配器、2026-11-17 收盘后真实公开响应样本、独立离线演示和一次性真实请求入口。数据库结构继续保持版本 5，核心依赖不变；AKShare 1.20.65 记录在独立的 `requirements-akshare.txt` 中，程序不会自动安装或升级。

项目只用于公开信息处理、个人研究记录和软件学习，不连接外部账户，不执行外部操作。程序不自动下单，不承诺收益。真实持仓只能由用户手动确认更新，模型无权修改。本地模型只负责摘要，不能修改原始数据和程序结论。敏感配置继续通过环境变量管理。C2 两份专用配置均关闭 Ollama 和云端。

## 一、当前完成范围

- 真实分钟接口固定显式使用 `period="1"` 和 `adjust=""`，内部映射为 `adjustment="none"`。
- 服务商无时区时间按固定 UTC＋8 解释，不读取 Windows 本地时区。
- 成交量由手乘 100 转为整数股；换算后不是整数时拒绝，不静默取整。
- 09:30 使用中性“特殊点”名称，保留原始行和排除原因，不改名为 09:31。
- 常规分钟严格限制在 09:31～11:30、13:01～15:00；保留 15:00，不制造 13:00。
- 14:59 零成交量、零成交额但 OHLC 完整的行会保留。
- `confirmed_through` 必须由调用方显式提供；`None` 表示全部未确认，最后一根已返回也不会自动确认。
- 请求代码、闭区间、必要字段、重复时间、乱序、空响应和成交量均在入库前检查；OHLC 继续由既有确定性清洗层检查。
- 每条常规分钟的 `raw_json.provider_raw` 保存原始行。真实请求另存完整 JSON 审计，包含 09:30 排除行、请求参数、行数、错误分类和入库摘要。
- 真实请求只写 `runtime/akshare-live-test.db`；离线样本只写全新的 `runtime/akshare-fixture-test.db`。两者均不接触主库。
- 当前没有接入自动轮询、前复权日线或交易日历，也没有修改 VWAP 摘要精度问题。

已保存样本证明收盘后静态结构可用，尚未证明盘中更新频率、最新分钟何时稳定或长期上游稳定性。

## 十、常见问题

### PowerShell 提示 `period=1` 或 `adjust=` 无法识别

这两个是 Python 参数，不是独立 PowerShell 命令。误输入只会产生 `CommandNotFoundException`，不会修改文件或数据库。后续只复制完整命令，不要单独输入参数。

### 激活脚本被执行策略拦截

继续直接调用：

```powershell
& $Python -m pandeng.app --help
```

不需要管理员权限，也不需要修改系统执行策略。

### 离线演示提示只允许指定数据库

恢复使用对应专用 YAML。不要把主库改名，也不要修改文件名检查来绕过隔离。

### 离线演示已有数据

这是防重跑保护。使用 `data-status` 和 `data-audit` 查看，不要删除数据库。旧 `real-data-test.db` 仍属于 C1，不会与两个 C2 新库混合。

### 体检显示 `unknown`

第一次 C2 验收显式使用 `confirmed-through none`，所以全部未确认，`unknown` 是预期结果。若同时存在缺口、质量错误或冲突，则停止后续分析并保留输出。

### 返回行数与示例不同

盘中部分数据、非交易日、上游变化和请求边界都会影响行数。真实空数据、部分数据和完整收盘后数据不能混为一谈，程序不会自动补齐缺失行。
